# 技术内容深度分析

## 使用场景

当需要读取 `knowledge/raw/` 中最新采集的技术项目，评估其技术价值、提炼亮点并发现行业趋势时，使用此技能。

## 执行步骤

1. 读取 `knowledge/raw/` 中最新的采集文件，确认数据来源、采集时间和待分析项目列表。
2. 逐条深度分析每个项目：撰写不超过 50 字的中文摘要；提炼 2 至 3 个以可核验事实为依据的技术亮点；按 1 至 10 分评分并说明理由；给出准确的标签建议。
3. 基于全部项目发现趋势，归纳共同主题、重复出现的技术方向和值得关注的新概念，并区分事实与推断。
4. 按下方格式输出分析结果 JSON；由于本技能仅允许只读工具，调用方负责保存输出内容。

## 评分标准

- 9-10 分：可能改变技术格局，具有显著突破、广泛影响或关键基础设施价值。
- 7-8 分：能直接帮助开发者或团队解决实际问题，具备明确的实用价值。
- 5-6 分：值得了解，提供有价值的新思路、工具或行业信息。
- 1-4 分：价值有限、相关性较低或信息不足，可略过。

## 注意事项

- 只分析 `knowledge/raw/` 中实际存在的项目；必要时使用公开来源核验项目描述、技术亮点和数据。
- 摘要必须使用中文且不超过 50 字，不得复述无法证实的宣传语或编造能力、性能与影响力。
- 每个项目的 `highlights` 必须包含 2 至 3 项，并以仓库说明、文档或可访问的公开资料为事实依据。
- `score` 必须为 1 至 10 的整数，`score_reason` 必须对应评分标准并说明具体依据。
- 每批最多 15 个项目中，9-10 分项目不得超过 2 个；若项目少于 15 个，仍不得超过 2 个。
- 标签应具体、可检索且不过度堆砌，例如 `LLM`、`Agent`、`RAG`、`推理框架`。
- `trends` 只总结多个项目共同反映的方向；无法从项目内容支持的结论必须标记为推断或不输出。

## 输出格式

```json
{
  "source_file": "knowledge/raw/github-trending-2026-07-26.json",
  "skill": "tech-summary",
  "analyzed_at": "2026-07-26T00:00:00Z",
  "items": [
    {
      "name": "example-ai-project",
      "url": "https://github.com/example/example-ai-project",
      "summary": "用于构建 AI 应用的开源工具，提供清晰的开发者集成方式。",
      "highlights": [
        "提供可复用的 AI 应用开发组件。",
        "公开文档说明了集成与部署方式。"
      ],
      "score": 8,
      "score_reason": "具备明确的开发者实用价值，能降低 AI 应用集成成本。",
      "tags": ["AI", "LLM", "开发工具"]
    }
  ],
  "trends": [
    {
      "theme": "AI 应用开发工具链",
      "type": "fact",
      "summary": "多个项目聚焦于降低 LLM 与 Agent 应用的集成和部署成本。",
      "evidence": ["example-ai-project"]
    }
  ]
}
```

`trends[].type` 只能是 `fact` 或 `inference`；`inference` 必须由 `evidence` 支撑，并在 `summary` 中说明其推断性质。
